# Problematic Read Causing Segfault in bwamem

## Read ID
VH01331:230:AAFJWJGM5:1:1508:27585:6642_GGCTCTTCGT

## Read 1
```
ATCGATGTGTGACGTCGTGCTCTCCCGGGCCGGGTCCGAGCCGCACGG
```

## Read 2
```
ACGAGGGGACCCCCGCGGGGCGGAGCGAGAAGGACGGTCCCGTTTCCAC
```

## Issue
This read pair causes a segfault (BrokenProcessPool) when mapping with multi-reference mode:
- References: genes_rRNA.fa + genes_tRNA.fa
- Crash occurs consistently at this read (position ~329,093 in test dataset)
- Single-reference mode may not crash

## Characteristics
- Read1: 49bp, high GC content, contains CG-rich regions
- Read2: 50bp, extremely high GC content (>80%), poly-G stretches
- Both reads have very repetitive sequence patterns

## Reproduction
```bash
# Extract this read:
zcat test1.fq.gz | grep -A 3 "VH01331:230:AAFJWJGM5:1:1508:27585:6642" > /tmp/crash_read1.fq
zcat test2.fq.gz | grep -A 3 "VH01331:230:AAFJWJGM5:1:1508:27585:6642" > /tmp/crash_read2.fq

# Reproduce crash:
coralsnake map -r genes_rRNA.fa -r genes_tRNA.fa -1 /tmp/crash_read1.fq -2 /tmp/crash_read2.fq -o /tmp/test.bam -t 1
```

## Root Cause
Likely a bug in bwamem's C code when handling:
1. Extremely GC-rich sequences
2. Multi-reference mate rescue logic
3. Alignment of highly repetitive sequences

The crash occurs during paired-end alignment, possibly in mem_matesw or mem_pair functions.
